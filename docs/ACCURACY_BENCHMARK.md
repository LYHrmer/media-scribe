# 听写匣内容正确性实测：Small 基线（2026-10-13）

**结论：当前 Small q4f16 已能正确识别两段干净普通讲话，但仍未满足歌词、极快中文、嘈杂中文、无语音误识别和中文标点要求。此批测试不能作为“准确率提升”的证据。**

共完成 11 个用例：6 段独立录音 / 视频音轨、3 个同源派生语音控制、2 个合成无语音控制，总音频时长 126.89 秒。没有把变体算作新说话人，没有利用参考文本引导推理。源提交 `afcff5a10372ed3d54ff14f84ed963d6a4c75563`，生产 Worker + Transformers.js 3.8.1 浏览器 bundle + 实际 ONNX WASM；模型、Worker 及资产哈希见 `benchmarks/results-small-production.json`。

执行方式为 Node VM Worker，模拟 Cache API 与本机同源模型 GET，WASM helper URL 映射为 `file:`。音频由 ffmpeg 解码；不是浏览器原生解码、Chrome 或华为真机验收。文字参考来源、样本权利和派生配方见 `benchmarks/case-provenance.json` 与 `../scripts/benchmarks/README.md`。

CER 为字错数 / 参考字数，先移除空格和标点，不是准确率。数字和繁简写法差异仍计入严格 CER；所以表中的 15.4% 与 38.5% 不能解释为对应比例的语义误识别。`digit_equivalent_cer` 只用于说明数字书写格式，不能抵消真正的号码错误。英语另算 WER。空参考以是否捏造文字判定，不把它包装成 CER 0。

标点与文字内容单独验收。输出冒号或括号内的字幕署名即使“有标点”，也不代表文本正确；完整要求必须同时满足文字正确与适合上下文的标点。英语逗号等有多种有效写法，不机械要求与稿件停顿完全一致。

## 改动必须过的回归

1. 任何候选模型 / 参数改动都复跑独立的快速中文、嘈杂中文、英语对白、用户歌词音轨；不要只拿歌词这一个片段验收。
2. 标点层在内容正确的前提下增补合理标点；保留修改前文本便于核对，不用给乱码添加标点来宣称成功。
3. 视频 OCR 按帧记录原始结果、置信度与字幕区域；用用户提供参考做测试后评分。OCR、语音结果和融合来源各自保留，不能把测试答案写入输出路径。
4. 噪声负例必须保留。当前的近静音分段无法拒绝有能量但无语音的噪声，不能靠升高音量阈值而损害低音量讲话。
5. 若文字只发生繁简和数字格式差异，需要固定的语言规范化层；自动严格字符评分与人工语义判读均应保留。

## 局限

这是小规模诊断 / 回归套件，未给出泛化“整体准确率”。中文普通短句参考来自提供方的官方示例输出，Qwen 示例参考来自提供方 transcript.txt，均不是这里新增的独立人工标注金标准；说话人性别尚未核验。当前套件还缺多种口音、多人重叠发言、真实会议 / 课堂、手机录音与不同浏览器环境；不能根据这次结果声称它们已被覆盖。公共示例音频和用户视频不提交 Git，仓库只提交测试代码、来源、哈希与文本结果。
