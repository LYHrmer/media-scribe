# B站音频接入核查与待确认事项

核查日期：2026-10-15。状态：**尚未确认满足“任意公开 B站分享链接、用户免第三方登录、无需安装”的官方音轨获取接口；线上完整验收未开始新一轮。**

本记录补充 [已有实现和实验](BILIBILI_VALIDATION.md)，不修改既有成功或失败结果。此前托管服务在视频信息接口收到 HTTP 412 / -412，消息为 `request was banned`；本轮只核查公开官方文档，没有继续请求被拒绝的视频接口、媒体地址或替代取音路由。

## 官方文档实际提供什么

| 能力 | 已确认内容 | 对本项目的结论 |
| --- | --- | --- |
| [外链播放器](https://player.bilibili.com/) | 官方提供 iframe 嵌入，参数包括 BV、av、CID、分P、自动播放、静音等 | 可用于播放。文档没有给出向宿主网页导出音频字节或 PCM 的接口，因此不能作为“已经取得音频”的验收证据。 |
| [查询单一视频稿件详情](https://openhome.bilibili.com/doc/4/d9554788-dcef-f139-6217-b487d41c3826) | Scope 为 ARC_BASE，需要申请权限和用户授权，查询授权用户稿件；响应列有 CID、filename、时长、share_url、iframe_url 等 | share_url 是播放页，iframe_url 是嵌入页，filename 是稿件内部标识。列出的响应字段没有媒体下载地址，不能把它们当成 MP3/M4A，也不能推断它允许获取任意第三方稿件的音轨。 |
| [开发者入驻](https://open.bilibili.com/doc/4/cbdcee3b-f57e-5c7b-cf27-83892fb811c4) | 当前公开指引写明暂未开通个人开发者入驻，要求企业资质等资料 | 需要按平台当时的实际准入条件核实；注册或取得应用密钥本身不等于获批音轨获取能力。 |

官方播放器与本应用来自不同源。浏览器的[同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)限制宿主直接访问跨源 iframe 的内部 DOM；给 iframe 添加 allow-same-origin 不会把 B站和本站变成同一个源。以上是技术能力核查，不据此宣称 B站不存在任何商务合作接口。

**结论：没有找到可直接替换当前实验取音器、同时满足原使用条件的已公开官方接口。** 需要平台进一步确认是否提供音轨访问合作，以及具体授权范围。不能承诺“接上 OAuth 就能提取任意 B站视频”。

## 接入前必须得到的具体信息

1. 平台是否允许第三方应用为转写获取完整音频，以及对象是任意公开稿件、已授权创作者稿件，还是双方约定的内容集合。
2. 官方接口文档与权限名称：返回完整音频流、带有效期的媒体 URL，还是只能返回播放页；是否支持分P、长度查询和错误状态。
3. 授权主体：开发者获得权限是否足够，还是每位内容作者或每位使用者都需授权。若需要使用者登录，应明确这不满足当前“用户免第三方登录”的要求。
4. 托管服务可用的访问条件、调用额度、域名要求，以及原始音频临时中转和转写结果的使用范围。

当前项目未取得上述音轨能力的确认。不要在代码中虚构官方 endpoint、把普通 ARC_BASE 权限包装成音轨权限，或要求用户提供浏览器 Cookie。应用密钥及访问令牌只应通过部署环境的受保护配置提供，不写入公开仓库、前端或聊天记录。

## 可交给平台审核的需求说明

项目：听写匣（media-scribe），开源网页转写工具，仓库 https://github.com/LYHrmer/media-scribe 。

希望用户粘贴公开普通视频链接，由服务取得所选分P的完整音轨并交给用户浏览器内的开源模型转写。用户无需安装客户端或购买模型 API。服务端不执行语音识别，不持久保存音频或转写结果。当前限制为每个分P不超过 30 分钟、音轨不超过 64 MiB。遇到登录、付费、地域、访问拒绝等限制时明确失败。

请确认是否存在支持上述用途的官方媒体访问接口或合作方案，并提供适用内容范围、权限申请条件、用户授权要求、接口文档和可用于验收的授权样本。特别需要确认：能否在普通使用者不登录 B站的条件下使用；如果只能处理作者授权的内容，请说明这一范围。

这份说明尚未向 B站提交，不代表已申请或获批。

## 取得接口后的线上验收

1. 从真实线上页面粘贴正常 BV/av、b23 分享文本和指定分P，验证音轨对应视频及分P；完整下载、解码后才进入转写队列。不能以标题、iframe 播放成功或服务端 HTTP 200 代替验收。
2. 对平台允许的固定样本，在实际浏览器里走完“取得音频—解码—本地模型—标点—编辑—导出”；记录浏览器和设备。Node/FFmpeg/WASM 适配层结果只作辅助，不能冒充手机或浏览器端到端结果。
3. 先独立标注中英文参考正文及标点，再做中文 CER、英文 WER 和标点核对。参考文本不传入模型；缺少逐字参考的样本记录准确率未评估。记录漏句、错分P、截断和错误的非空输出。
4. 核对取消、网络中断、音频缺失、平台拒绝、超长及无权限内容的提示与旧稿保留。公开失败记录，不更换失败样本、不合并多轮结果包装成一次全通过。
5. 当前十条冻结样本只有在接口权限覆盖它们时才复用；否则在请求前确定新的授权清单，单独报告，不与旧清单混算。
