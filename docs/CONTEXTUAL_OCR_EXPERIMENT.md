# 本地 OCR 语境候选重排实验

**结论：完整增强观测可以生成较完整的待核对草稿；当前生产 mobile 原色识别没有同等能力。此实验未默认部署，也不允许静默改写原文。**

结果和公共模型指纹见 [精简机器可读证据](benchmarks/contextual-ocr-summary.json)。没有提交用户媒体、本机路径、模型权重或依赖本机绝对路径的实验脚本。

## 全量结果与来源消融

输入共58条OCR观测，实际是19个采样时刻：首句6条/6时刻，后句52条/13时刻（mobile/server × 原色/green），不是58个独立帧。全增强生成的**待核对草稿**为：

> 漫天红伞无人生还。  
> 我的遗憾是不能洁白的带你离开。

“漫”继承可靠OCR，没有换成参考答案中的其他字。推理不使用参考文本或歌词提示。

每组先独立重算生产 `fuseVideoCaptions`，再使用同一候选重排流程，避免mobile组继承server的字位信息。

| 识别来源 | 观测数 | 后句待核对结果 |
|---|---:|---|
| 当前mobile，仅原色 | 19 | 我的退修是不能洁白的带你离开。 |
| mobile，原色+green | 32 | 我的遗是不能洁白的带你离开。 |
| mobile+server，仅原色 | 32 | 我的的博是不能洁白的带你离开。 |
| mobile+server，原色+green | 58 | 我的遗憾是不能洁白的带你离开。 |

关键限制：**“憾”只有server-green在13.125秒的真实观测提供，字形分数0.353959；mobile两组没有该候选。** “遗”的最高字形分数0.921843来自14.125秒server-green。不能仅添加语言模型，就宣称当前小模型已能完整恢复这一字幕。

## 流程与约束

1. 全部观测按融合时段聚类；窗口间隔≤0.15秒合并，邻近1秒内被fusion过滤的边缘观测仍纳入审计。fusion采样间隔参数为0.25秒。
2. 按可靠性、独立时刻support、置信度选主假说；`observedText`必须匹配真实OCR读数，用其逐字横坐标中位数建立几何锚点。
3. 只处理显式不确定替换/插入槽。插入还须有≥1.6倍中位字距的内部空隙；原始字形只归给最近槽位，最大距离为0.65倍中位字距。每个候选保留模型、通道、时间、原字位和字形分数。
4. 已有字形置信度≥0.90的原字符锁定，不调用语言模型。插入槽没有可靠原字符，先以最强视觉候选初始化。
5. 仅在不确定槽mask当前字，以 `ln(字形分数) + 0.35 × MLM logP` 对**已有同位候选**排序，最多两轮。该分数未校准，不能解释为正确率。

全增强的真实锚为“我的遗是…”，插入槽汇集25个原始候选。纯视觉seed选“博”（0.905858）；语境模型将已存在的“憾”排首位，形成“我的遗憾是…”。其它正文继承原锚，没有自由补写缺词。去掉“憾”视觉候选后，模型选“博”，没有重新生成“憾”。所有新建议仍标为待核对，原OCR文字保留。

## 独立对照与反例

| 输入 | 候选内建议 | 结果 |
|---|---|---|
| 今天天汽很好 | 今天天气很好 | 改善 |
| 请喝一杯永 | 请喝一杯水 | 改善 |
| 我对此深感遗撼 | 我对此深感遗憾 | 改善 |
| 她叫张欣今天来开会 | 她叫张新今天来开会 | **人名误改，原文必须保留** |

高置信字、人名、谐音和否定词锁定对照均未改动。低置信人名反例说明语言流畅度不是视觉证据，当前结果不通过自动纠错门槛。

## 真权重、量化与WASM验证

使用公开已训练 [voidful/albert_chinese_tiny](https://huggingface.co/voidful/albert_chinese_tiny)，revision `62e436eea35e6cb02d9464b26636c90c7624ae1e`。加载无missing/mismatched权重，仅未使用pooler；官方例概率复现为0.403126，官方值约0.403123。词表为21128项，与官方BertTokenizer校验一致；必须按LF分行，不能用会拆开词表内Unicode分隔字符的 `splitlines()`。

| 资产 | 字节 | 大小 |
|---|---:|---:|
| FP32 MLM ONNX | 16,273,104 | 15.52 MiB |
| 每行权重量化int8 QDQ MLM | 4,345,470 | 4.14 MiB |
| 词表 | 109,540 | 0.10 MiB |
| 增强实验所用v4 server识别模型 | 90,530,732 | 86.34 MiB |

MLM加词表约4.25 MiB；量化只声明下载体积减少，不声明运行时内存或计算加速。int8 SHA256：`c499070944899c33234fdc4f58116cae8c6e7c028aa2fca69e456f7d5f839049`。其它指纹见JSON。

真实ONNX Runtime Web WASM `1.22.0-dev.20250409-89f8206ba4` 在Node中执行。FP32对Torch候选logit最大误差约0.0000174；int8最大误差0.335，语境排名9/9一致，视觉混合排名8/9一致。差异来自故意缺少正确候选的近似平局：FP32保留“汽”，int8选“泣”；均没有生成候选外的“气”。

全增强和生产mobile各自的完整流程也通过int8 native/WASM排序一致性验证，最大logit误差分别约0.0000286和0.0000420。本机单线程int8约10.3毫秒/不确定位置，session初始化约34毫秒；未验证浏览器UI或移动设备性能。

## v5 mobile轻量替换探针：本样本未改善

核对 [RapidAI官方模型清单](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml) 后复用现有PP-OCRv5 mobile识别权重：16,631,306字节（15.86 MiB），SHA256 `5825fc7ebf84ae7a412be049820b4d86d77620f204a041697b0494669b1742c5`。内嵌字典加CTC blank/space共18385类，与模型输出一致。

13.125秒同一真实裁片仅测四个变体：

| 处理 | 输出 |
|---|---|
| 原色 | 我的遗加是不能告日，的带你离开 |
| green | 我的过加是不能告日，的带你离开 |
| 原色横向1.5倍 | 我的过加是不能当日的带你离开 |
| green横向1.5倍 | 我的过是不能当日，的带你离开 |

四组已解码字位的Top5均没有“憾”。因此停止扩展，没有推动v5替换生产模型。

## 部署边界

本实验只证明“有正确视觉候选时，本地语境重排能帮助形成待核对草稿”。完整样本恢复依赖较大的server和green增强，当前mobile默认路径仍有缺字。没有默认部署新模型，也没有将草稿当作已核验正文。输入媒体不入仓；重跑具体样本需要原始会话输入，流程、参数与关键来源已在此记录。
