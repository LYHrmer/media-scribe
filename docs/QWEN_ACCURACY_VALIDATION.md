# Qwen、口音采访与声画核对验证（2026-10-14）

本文保留 v0.5.3 的完整句与连续批次实验。v0.5.4 的逐段独立 Worker、固定分段、歌词配对与资源修复另见 [继续验证记录](LIFECYCLE_LYRICS_VALIDATION.md)，后续成功不覆盖本文的失败历史。

本轮找到了值得继续验证的识别改善：预先冻结的 8 名新说话人中，原生 Qwen 0.6B INT8 的中文 CER 从默认方案的 5.45% 降至 4.09%；官方 1.7B BF16 的英文 WER 从 19.42% 降至 8.70%。这些改善尚未产品化。每种语言仅 4 人，部分样本退步，歌词仍未解决，直接 Qwen 在静音与噪声上仍会产生文字，不能据此承诺全面替换现有模型。

v0.5.3 的产品改动是狭窄的标点格式修复，保留 `rawText`；没有把近 1 GiB 的 Qwen 权重加入轻量网页默认流程。原生研究结果和真实 WebAssembly 执行也不等于手机浏览器验证。公开数值、来源指纹与逐样本错误数见 [机器可读报告](benchmarks/qwen-accuracy-20261014.json)，复现代码见 [研究工具说明](../research/qwen-20261014/README.md)。

## 实验范围

对照方案为当前默认中文 SenseVoice Small int8 加 VAD/标点、英文 Whisper Small q4f16；三个研究候选分别为原生 Sherpa Qwen3-ASR-0.6B INT8、官方 Qwen3-ASR-0.6B BF16 和官方 Qwen3-ASR-1.7B BF16。三个原生候选均完成 31 个输入并正常退出。**31 个输入不是 31 名新说话人，也不是 31 段新采集的真实视频。**

- 23 段 MELI 采访：既有 15 段来自 14 名说话人，作为开发/回归集；新 8 段来自 8 名与旧组不重叠的说话人。合计 22 名独立说话人。
- 8 项分开评分的控制：6 个既有真实录音/视频音轨，包括已见的私人歌词音轨；另有 2 个合成无语音控制。它们不计入新说话人结果。
- 默认方案的新 8 段采访与私人歌词来自本轮实际编译 Worker/WASM；旧 15 段采访和另外 7 项控制复用带来源指纹的既有真实推理，没有声称默认方案全套重新运行。

输入使用冻结的 16 kHz PCM，不按识别成绩更换片段、裁剪、降噪、增益、语速或热词。参考文本只进入独立的事后评分程序。**没有微调或训练模型，没有把用户音视频上传到外部 ASR，没有将已知歌词答案加入规则或提示。** 模型权重下载不涉及媒体上传。报告不公开私人视频、转写、歌词、字幕、整份 MELI 参考或大段模型输出。

## 样本和参考限制

数据来自 Suyuan Liu、Molly Babel 的 [MELI: Mandarin-English Language Interview](https://doi.org/10.5683/SP3/5WMRUO)，版本 1.2，许可 CC BY-NC-SA 4.0。新样本总长约 230.82 秒，旧样本约 465.72 秒。取参与者左声道，固定重采样；测试的是单人完整回答，不是完整双人问答、说话人分离或长时间多人转写。

新英语组按元数据顺序选择英语起始年龄大于 6 岁的未用说话人；新中文组按顺序选择其余有地区信息的未用说话人。每人取第一个符合事先规定的 18–45 秒完整回答，保留停顿、重复、口误和原有语法，不按音质或模型得分筛选。地区和语言学习经历不是独立评定的口音强度，不能称为“重口音全面通过”。

预选 M98A 没有符合规则的完整回答，缺失状态与筛选记录保留；随后另行冻结下一名未用参与者 F03A，再读取其标注，全部音频区间在下载和推理前冻结。最终分析分母是 **8 名有合格样本的新说话人，中文 4 人、英文 4 人**。看过本轮成绩后，如果继续针对这些样本调参，它们不能继续充当未接触的新留出集。

参考采用官方 `utterance-corrected` 层：Whisper-large-v3 草稿由双语研究助理校正。它不是从零独立转写的完美金标准，可能存在残留标注偏差。本轮按既定规则移除非语音标记和半词片段，其余完整字词、填充词和重复保留。**MELI 普通标点缺少可靠金标准，标点准确率记为 N/A。**

## 四方案的采访结果

中文报告字错误率 CER，英文报告词错误率 WER，均为 `(替换 + 删除 + 插入) / 参考单位数`，越低越好。主指标沿用既有 NFKC、小写、标点/空白处理，不折叠数字形式或繁简体。按语言及开发/留出分组，不把 CER 和 WER 合成一个总准确率。下面是完整分组的加权错误率，分母与失败项不会因为输出不好而删除。

| 分组 | 片段 / 组内说话人 | 默认方案 | 原生 0.6B INT8 | 官方 0.6B BF16 | 官方 1.7B BF16 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 新中文，440 字 | 4 / 4 | 24/440，5.45% | 18/440，4.09% | 23/440，5.23% | 22/440，5.00% |
| 新英文，345 词 | 4 / 4 | 67/345，19.42% | 46/345，13.33% | 39/345，11.30% | 30/345，8.70% |
| 旧中文，598 字 | 6 / 6 | 26/598，4.35% | 22/598，3.68% | 25/598，4.18% | 22/598，3.68% |
| 旧英文，733 词 | 9 / 9 | 127/733，17.33% | 82/733，11.19% | 69/733，9.41% | 78/733，10.64% |

新中文 INT8 的错误数相对减少 25.0%，绝对下降 1.36 个百分点；新英文官方 1.7B 的错误数相对减少 55.2%，绝对下降 10.72 个百分点。这是这批固定小样本的对照，不是对所有人、所有口音的提升承诺，也不构成“更大模型总是更准”的结论。

为避免长回答主导结果，同时给出新说话人等权均值；每个语言组各 4 名说话人：

| 指标 | 默认方案 | 原生 0.6B INT8 | 官方 0.6B BF16 | 官方 1.7B BF16 |
| --- | ---: | ---: | ---: | ---: |
| 新中文说话人平均 CER | 5.68% | 4.39% | 5.52% | 5.50% |
| 新英文说话人平均 WER | 18.70% | 12.96% | 11.37% | 8.54% |

23 段采访逐例比较，INT8 为 16 改善、5 持平、2 退步；官方 0.6B 为 13 改善、9 持平、1 退步；官方 1.7B 为 15 改善、5 持平、3 退步。全部退步如下，不能用平均提升掩盖：

| 候选 | 样本 | 默认错误数 → 候选错误数 |
| --- | --- | ---: |
| 原生 0.6B INT8 | 旧中文 F02B | 2/83 → 3/83 |
| 原生 0.6B INT8 | 旧中文 M01B | 1/70 → 2/70 |
| 官方 0.6B BF16 | 旧中文 M00B | 3/54 → 4/54 |
| 官方 1.7B BF16 | 旧英文 F00A | 4/52 → 5/52 |
| 官方 1.7B BF16 | 旧中文 M00B | 3/54 → 5/54 |
| 官方 1.7B BF16 | **新中文 F94B** | **9/111 → 11/111** |

新英文 INT8 的替换/删除/插入从默认的 22/42/3 变为 24/19/3，主要改善是漏词减少，替换反而多了 2 处。完整逐样本分母、替换/删除/插入与输出哈希保留在机器报告中，不只展示改善例。

## 控制集：歌词和无语音仍未解决

以下六项语音控制报告错误数/参考分母，中文使用严格 CER 的字数，英文使用 WER 的词数。私人歌词是已见开发控制，不是新采访留出。

| 控制 | 默认方案 | 原生 0.6B INT8 | 官方 0.6B BF16 | 官方 1.7B BF16 |
| --- | ---: | ---: | ---: | ---: |
| 清晰中文 | 0/13 | 2/13 | 7/13 | 7/13 |
| 清晰英文 JFK | 0/22 | 0/22 | 0/22 | 0/22 |
| 快语速中文 | 20/130 | 17/130 | 18/130 | 17/130 |
| 嘈杂中文数字 | 46/53 | 20/53 | 10/53 | 1/53 |
| 嘈杂英文对话 | 9/31 | 3/31 | 3/31 | 1/31 |
| 已见私人歌词 | 20/22 | 20/22 | 16/22 | 19/22 |
| 静音误报 | 无 | 有 | 有 | 有 |
| 合成噪声误报 | 无 | 有 | 有 | 有 |

清晰中文中，INT8 的 2 处差异只是阿拉伯/汉字数字表达；两个官方模型输出相同，另有 5 处繁简字形差异，没有时间数值或词义错漏。因此不能将 7/13 解释为内容严重识错。严格 CER 保留原值；既有数字等价次指标分别为 0、0、5/13、5/13，不做繁简转换，也不根据成绩换主指标。

嘈杂数字和英文对话得到明显改善，但歌词错误仍很多，尚未满足用户要求。默认中文流程有 VAD，直接 Qwen 研究运行没有 VAD；静音/噪声误报比较的是完整系统，不能全部归因于声学模型。空参考的 CER/WER 没有定义，报告误报而不是写成 0%。

## 解码、原始输出和失败记账

原生 INT8 使用 Sherpa-ONNX 1.13.8、ONNX Runtime 1.28.2、CPU 两线程、greedy 解码、`max_total_len=2048`、`max_new_tokens=512`、固定语言和空热词。模型与 tokenizer 共 987,015,347 字节，约 941.3 MiB。另有旧 512/128 限额的六例历史复现，单独记录，不与主实验逐例选优拼接。

Sherpa 的 `text`/`tokens` 是引擎处理后的返回值；该版本含 64-token 低多样性重复尾部保护。返回 token 数为 2–132、低于 512，并不能证明内部生成从未截断。公共报告将原生真实截断计数标为未知，不能写成 0；没有捕获保护警告也不等于完整生成序列未经修改。我们没有在其返回文字上追加基于参考的替换或清理。

官方 BF16 使用本地固定 revision、CPU 两线程、batch size 1、greedy 解码、512 个新 token 上限和同一冻结 PCM。主输出仅对新生成的 token 后缀执行 `tokenizer.decode`，跳过特殊 token，保留重复；官方 `processed_text` 仅作诊断，不能根据参考得分挑选更好的一版。两种官方模型均为 31/31 正常退出，原始生成和 EOS 证据未发现截断或触及新 token 上限。

原生 INT8 与官方 BF16 同时存在量化、运行库和解码实现差别，不能把所有分数差异都归因于量化。评分器校验 PCM、清单、参考和结果指纹；非零退出、缺失、错误或未终止的批次不能产生完整分组准确率，调用参数和内嵌退出码冲突会拒绝评分。成功子集仅另列诊断，不替代原始失败分母。

## 真实 WebAssembly 执行与产品边界

使用包含 Qwen 支持的官方 `sherpa_onnx_web 1.13.8` JS API 和真实 WASM，在具备浏览器全局对象的 Node VM 内运行。它不是原生推理的改名，也不是 Chrome/华为手机 UI 测试；媒体解码、网络下载、缓存、取消、重试和移动端内存没有因此获得验证。

实际 WASM 初始堆为 512 MiB、最大为 2 GiB。Web runtime 的构建 commit 为 `8b5a9990`，原生为 `11afbd00`，线程数也不同，不能声称它们是完全相同执行环境，或将差异单独归因于平台。

- 5.592 秒短句成功，实际解码约 5.446 秒；单句的成功不代表全部长音频或连续处理通过。
- 2048/512 配置连续运行 31 例：前 8 项控制完成，在第 9 例、首个 25.620625 秒 MELI 回答发生 runtime abort；1 例失败、22 例未尝试，23 项 MELI 无完成结果，完整批次与 MELI 准确率均为 `null`。
- 失败时记录的 WASM 堆达到 2 GiB；这不足以仅凭 abort 确诊内存不足。相同配置、相同输入在新进程中成功，解码约 28.02 秒，因此不能写成“25 秒长句必然失败”。这次单例诊断不会补进失败批次改写成绩。

随后另行冻结 `1280/512` 配置进行完整连续批次诊断：只降低 KV 容量，没有截短输入或降低 512 个新 token 的预算。这次完成 10/31 例，在第 11 例 `meli-m00a-zh` 再次 abort，退出码为 1；其中 8 项控制与 2 项 MELI 完成，1 项 MELI 失败，20 项未尝试。失败时记录的 WASM 堆为 2 GiB、进程 RSS 为 2,402,598,912 字节。完整批次和完整 MELI 组准确率仍为 `null`；8→10 是执行完成数，不是准确率提升，不能把两批成功结果拼起来宣称通过。

降低 KV 容量未解决连续运行稳定性；进程生命周期或工作区占用可能相关，确切 abort 原因未确定。以上内存为记录时点值，不是连续测量的峰值，也不是手机内存实测。各次运行保留独立输入、配置和结果，不覆盖失败记录。本轮停止推理，Qwen 不接入产品；引擎返回的时间轴字段为空，也没有获得可靠逐词对齐能力。

## 声音与字幕核对：真实视频没有改善

恢复的两份用户视频具有相同 SHA-256，实际上是一份约 21.75 秒素材；它早已参与开发，不能算两个独立新样本。正确应用旋转元数据后，固定每 0.5 秒抽帧，末尾一个时刻没有可解码帧，明确记录缺失；最终使用 43 个不同时刻，裁剪变体不冒充独立帧。

实际 PP-OCRv4 mobile 编译 Worker/OpenCV/ONNX WASM 得到 29 条原始文字读数，平均约 5.86 秒/帧。原生产融合只在前半段形成两段较稳定证据，后半段仍缺字、错字。没有正确文字候选时，多帧重复或较高平均分不能凭空修复它。

独立核对候选要求非近似语音时间轴、至少三个独立时刻、逐字分数、变化字幕轨、同时间局部高相似及无冲突。标题、常驻文字、错时画面、互相矛盾的屏幕与缺少时间轴的结果均不能覆盖正文；建议保留原文、来源、几何和时间，必须人工确认。

20 项程序控制通过，但真实开发视频回放产生 **0 条可用建议、0 次正文替换**；历史 Qwen 输出缺少时间轴，不能套用另一模型的时间。真实正文错误率没有因此下降，候选未集成产品。竖排、小字与模糊字幕召回不足，OCR 正确候选缺失，以及字幕与声音本身不一致，仍是未解决问题。

## v0.5.3：修复紧邻逗号和句号

真实 SenseVoice 输出出现 `，。`。该串已存在于 ASR 原始输出，后续标点模型只是保留已有标点。修复仅作用于 `normalizeSensePunctuation`：删除紧邻中文句号前的中文逗号，沿用既有重复句号处理，并按字符偏移同步处理跨 token 情形，保留存留 token 的来源时间戳。完整原文继续保存在 `rawText`，字词不变；正常 `？！`、`！？`、省略号、引号、空白和换行保持。

相关 17 项检查通过，覆盖不同 token 切分、补充平面字符、正常标点保持及无效时间轴回退；生产完整 `npm test` 为 204/204 通过，公开评分器另有 15/15 项通过。完整 `npm run build` 正常结束。随后使用实际编译出的 ASR、VAD、标点 Worker 和真实 WASM 重跑私人歌词控制：正常退出，紧邻逗号已清理，`rawText` 逐字保持、词汇正文保持，识别错误率没有改善。HTTP、Cache API 和 Worker 传输由本地替身提供，不是手机 UI 验证。

无转写正文的证据见 [v0.5.3 编译推理收据](benchmarks/v053-punctuation-smoke.json)，含 Worker/runtime 与前后结果哈希。**这是标点格式修复，不是口音或歌词识别准确率改善。**

## 公开证据和后续采用条件

[机器报告](benchmarks/qwen-accuracy-20261014.json) 保留模型 revision、资产 SHA-256、输入/参考/输出哈希、四方案逐例分数、说话人分母、退步例、控制集误报、失败终态和 Web 诊断。[研究目录](../research/qwen-20261014/README.md) 提供冻结协议、下载器、推理与独立事后评分脚本；模型、媒体、参考和完整输出不随仓库发布。

本轮只把已验证的标点修复纳入产品。Qwen 的本地准确率改善还需独立新说话人复核、无语音保护、连续运行稳定性和真实手机端的下载/缓存/内存验证；不能把重模型原生实验成功等同于轻量浏览器能力。声音与画面候选也需要在新的真实有字幕材料上取得可靠增益，才有集成依据。
