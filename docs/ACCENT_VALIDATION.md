# v0.5.2 口音采访与窗口合并验证（2026-10-14）

本轮采用一项范围有限的英文窗口合并保护：在严格条件下，保留模型已经生成、且时间戳完整闭合的文字，避免把时间戳显示为不相交的正文交给跨窗口匹配。**默认英文模型仍为 Small q4f16，仍使用 30 / 5 窗口；11 个默认模型用例的正文逐字未变，不能宣称默认词准确率提高。** 短窗口、时长守卫及其他替代模型均未采用。

该变更已采用到 v0.5.2，发布进行中。编译后的 Worker 与真实 WASM smoke 已通过，201 项代码测试全部通过，完整静态构建成功。下文区分真实模型推理、保存 token 的离线重放以及代码测试，不把三者算成重复的独立录音实验。

对应的 [候选结果 JSON](benchmarks/accent-results.json) 保留原有 14 次完整运行、59 次用例推理及全部失败；另有 [合并验证 JSON](benchmarks/merge-results.json)，保留新增的 11 例真实模型观察和同 token 的完整解码前后比较。两份文件均记录模型与运行 SHA、音频与参考 SHA、实际输出和逐例评分，不包含参考全文、源音频、完整标注或本地路径。离线重放没有再次调用声学模型，重复推理也不是新增独立样本。

## 新样本与验证边界

本轮新增 MELI 1.2 的 9 段自然采访回答，9 位不同受访者，共 **281.0614375 秒**。连同之前 6 段，累计 **15 段、14 位受访者、465.7175 秒**；M00A 的中英文为同一人，没有替换难例。参考来自官方 `utterance-corrected` 标注：Whisper-large-v3 初稿经双语研究助理校正；不是待测模型输出，也不是完全从零人工转录。参考仅在推理完成后评分，不传入模型、提示词、词典或输出修补。

| M99A | 英文 / 38.39 秒 | 普通话背景，英语 6 岁开始 | 时长守卫规则冻结后选定的最终验证 |

语言背景来自公开元数据，**没有独立评定每段可听口音的强弱**，不能将本组包装为强口音或完整方言基准。前 5 例的结果后来已用于开发，不能再称为最终未参与调参的留出集。F94A / M99A 只独立验证当时已冻结的时长守卫；F95A / F96A 是之后为合并候选另选的两人，不能混用验证用途。

选择规则先于相应样本的推理结果冻结：前 5 例使用指定参与者的首个合格、完整连续回答，范围 18–40 秒；时长守卫的 2 例按官方元数据顺序选择此前未使用、英语起始年龄至少 6 岁的前两人，再取首个合格 30–45 秒连续回答。只排除整段包含听不清或隐私隐藏标记的回答，不按 RMS、音质或模型表现筛选。保留内部停顿、口语重复和语气词，不拼句，不增益、不降噪、不变速。

合并候选的 F95A / F96A 沿用相同规则，在元数据中排除此前全部 12 位受访者，按顺序取新的两人。参与者先于标注读取冻结，完整区间先于音频下载冻结；两例源片段重新离线生成的 PCM / 参考 SHA 均与初始清单一致。它们不是从已有失败或成功输出中挑出的“好听片段”。

原始录音仅左侧受访者声道具有完整标注，因此这里只评估受访者连续回答，不验证整场双人采访、说话人分离或串音处理。原始 44.1 kHz 左声道按固定方法重采样为 16 kHz float32 PCM；来源区间、标注与 PCM SHA 已冻结。通过 HTTP Range 下载源片段，未下载完整 WAV，因此完整源 WAV 的上游 MD5 明确标为未在本地验证。

MELI 标注省略普通句末标点，**本组标点正确率为 N/A**；JSON 覆盖了原评分器对此无效的标点计数。产品输出中的标点仍保留，不能据此认定其全部正确。中文使用 CER、英文使用 WER，均为替换、漏字词、插入的编辑距离除以参考长度，越低越好。口语填充词、真实重复和语法不规范仍计入参考；不存在“自动润色后更像书面语便算正确”的加分。

## 短窗口：开发改善没有推广到最终验证

默认英文配置为多语 Whisper Small q4f16、时间戳解码、30 秒窗口 / 5 秒重叠。无条件缩短为 20 / 3 后，新开发集出现两例改善、一例退化：

| 英文开发用例 | 默认 WER | 无条件 20 / 3 WER |
|---|---:|---:|
| F02A | 10/75 = 13.33% | 6/75 = 8.00% |
| M01A | 9/58 = 15.52% | 16/58 = 27.59% |
| F89A | 16/60 = 26.67% | 8/60 = 13.33% |

M01A 只有约 22 秒，额外分窗产生了重复内容。因此提出第二个候选：**仅实际音频范围超过 30 秒才用 20 / 3，其他范围继续 30 / 5，保留时间戳**。规则冻结后才选择 F94A / M99A，未按它们的输出重调阈值。

| 最终验证用例 | 默认 WER | 有时长守卫的 20 / 3 WER |
|---|---:|---:|
| F94A | 11/116 = 9.48% | 21/116 = 18.10% |
| M99A | 12/69 = 17.39% | 14/69 = 20.29% |
| 固定两例按参考词数合计 | 23/185 = 12.43% | 35/185 = 18.92% |

两例均退化，合计增加 12 个词错，**拒绝这个守卫候选**。这项合计仅描述固定的 185 个参考词，不是英语总体准确率。此前开发集中的改善不能覆盖最终验证的失败，也不能通过全局删除重复词来修饰结果，因为自然说话本来包含真实重复。

## 其他英文模型：旧两例开发对照

下列候选均在原有 F00A / M00A 两例比较；基线来自 [上一轮公开记录](INTERVIEW_VALIDATION.md)，没有把它们冒充本轮新受访者。模型候选没有在最终 2 例上获得独立通过证明。

| 配置 | F00A WER，52 词 | M00A WER，103 词 | 已观察的结果 |
|---|---:|---:|---|
| 默认 Small q4f16，30 / 5 时间戳 | 4/52 = 7.69% | 27/103 = 26.21% | 对照 |
| Small q8，30 / 5 时间戳 | 31/52 = 59.62% | 26/103 = 25.24% | 首例严重遗漏；不能直接替换默认 |
| Small q8，30 / 5 正文 | 4/52 = 7.69% | 30/103 = 29.13% | 与旧正文重试词错数相同，后一例仍差于默认 |
| Small.en q4f16，30 / 5 时间戳 | 6/52 = 11.54% | 29/103 = 28.16% | 两例均退化，不采用 |
| SenseVoiceSmall int8，指定英语 | 5/52 = 9.62% | 30/103 = 29.13% | 两例均退化，不采用 |
| Distil-Small.en q8，30 / 5 时间戳 | 4/52 = 7.69% | 31/103 = 30.10% | 首例持平，后一例退化，不采用 |

Distil 的 F00A 返回了粗略时间范围及时间戳警告，未据此声称字幕时间精确。运行耗时保存在 JSON 中，但 Node 宿主、冷启动和缓存会影响耗时；本报告不将这些数当成手机速度承诺。

q8 的只读生成探针已完成重跑：相同 PCM、完整结果对象、输出文字及 31/52 词错均与原候选相同，探针没有改变识别结果。首次探针的可选解码诊断调用失败，修复后重新运行并通过等价检查；首次失败不记为诊断成功。之后的离线重放定位了一个合并遗漏路径，见下一节；这仍不能解释所有声学误听，也没有让 q8 替代默认模型。

## 采用的窄范围合并保护

q8 的 F00A 诊断中，第一窗音频覆盖 0–30 秒，但最后一段完整正文的预测结束时间为 19.76 秒；下一窗实际从 20 秒开始。原解码器仍因右侧重叠参数而延后关闭这段正文，再将它与下一窗不同内容交给最长公共序列合并，导致已生成的阅读、写作和发音相关文字消失。同一组保存的 token 能精确重放原始遗漏；候选合并保留了这些文字。

保护仅处理 Small / 英语 / 转写 / 布尔时间戳模式，限定 Transformers.js 3.8.1。它要求从首个无左重叠窗口起，连续的正文段时间戳有效、单调且完整闭合，末端至少早于下一窗实际起点一个时间刻度；遇到未闭合、正文时间戳跨入下一窗、无效时间或待处理的前窗状态便保留原行为。只复制解码所用的窗口元数据，保持原来的时间偏移；不改音频、生成 token、模型权重或 30 / 5 物理分窗，也不增加一次模型推理。临时修改仅针对当前 tokenizer 实例，完成或异常后恢复。

模型预测时间戳可能不准，所以这不是所有重复或遗漏的通用解法。没有全局删除重复词，没有依据参考答案、文本长短或“自信程度”选择输出。

### 默认 q4f16：11 例真实采集后重放

实际 WASM 再采集 11 例原始合并输入与输出，其中 9 例有历史结果，**文字、所有字幕段与时间、模式和警告的完整对象均与历史结果相同**；新两例无历史基线，不把“没有可比项”记为通过。随后恢复原始 number / BigInt token 类型及精确 stride，对每例重放原解码器和完整 Worker 结果，11/11 精确一致，再比较实际生产 `.js` 保护与原解码行为。

| 默认模型的固定用例 | 原合并 WER | 候选合并 WER | 保护是否触发 |
|---|---:|---:|---|
| F00A | 4/52 = 7.69% | 4/52 = 7.69% | 是；仅字幕从两段变为三段 |
| M00A | 27/103 = 26.21% | 27/103 = 26.21% | 否 |
| F02A | 10/75 = 13.33% | 10/75 = 13.33% | 否 |
| M01A | 9/58 = 15.52% | 9/58 = 15.52% | 否 |
| F89A | 16/60 = 26.67% | 16/60 = 26.67% | 否 |
| JFK 控制（演讲，非采访） | 0/22 = 0% | 0/22 = 0% | 否 |
| 嘈杂对话控制 | 9/31 = 29.03% | 9/31 = 29.03% | 否 |
| F94A（原时长守卫验证） | 11/116 = 9.48% | 11/116 = 9.48% | 否 |
| M99A（原时长守卫验证） | 12/69 = 17.39% | 12/69 = 17.39% | 否 |
| F95A（新合并留出） | 28/96 = 29.17% | 28/96 = 29.17% | 否 |
| F96A（新合并留出） | 10/104 = 9.62% | 10/104 = 9.62% | 否 |

11 例正文逐字相同，固定词数合计 **136/786 → 136/786**。F00A 仅把原来跨两窗的字幕段分开，正文不变；其余完整结果对象均不变。新两例保护均不触发，因此提供的是未误伤正常路径的证据，不能说它们证明了触发分支对未知口音的纠错效果。候选字幕均完整覆盖正文，这也不等于逐字时间对齐已得到人工验证。

### q8 诊断：同一批 token 的合并比较

已看过的 F00A q8 诊断在相同 token 离线重放中，词错数由 **31/52 → 4/52**，即 59.62% → 7.69%。原解码器精确复现原模型输出，候选保护恢复了已生成、被合并误删的内容。这个数来自离线解码，**不是新的模型推理，不是未参与开发的留出结果，也不是默认 q4f16 的准确率改善**。仍有 4 个词错，不能标为逐字通过。

源码中的 `tests/whisper-merge-replay.fixture.json` 保存一小份真实生成 token 和模型解码结果，用于回归这个路径；没有保存人工参考全文或音频。它采用 MELI 衍生内容的 CC BY-NC-SA 4.0 许可，明确区别于应用代码 MIT。该 fixture 使用真实 Transformers.js 解码/合并代码，有限 token 文本映射曾与完整官方 tokenizer 校验；它属于解码回归测试，不另算一条自然采访或一次模型推理。

## 完成证据、复现和许可

Whisper 结果需同时具备完整用例数量、`completed_at` 和日志末尾 `COMPLETE`；不把仍在写入的中间文件计为成功。SenseVoice runner 只在所有用例完成后写结果文件，不打印 `COMPLETE`，本报告另核对每例日志的顺序和文字。模型成功运行与文字逐字正确是两件事，前者不代表后者。

运行实际使用生产或隔离候选的模型、构建 Worker / Transformers.js 3.8.1 和真实 WASM；HTTP、Cache、Worker 传输在 Node VM 中模拟。这里只允许本地媒体读取及模型资产 GET，不将受访者录音上传远程模型。它不覆盖真实手机浏览器解码、鸿蒙兼容性、整段录像 OCR 或 UI 操作。没有训练、微调、修改模型权重，也没有用参考答案改输出。

`scripts/benchmarks/prepare-meli-interviews.py --accent` 可恢复前 5 例，`--accent-final` 恢复时长守卫 2 例，`--merge-holdout` 恢复合并候选 2 例；这些开关与原有 `--holdout` 互斥，默认 4 例及旧保留验证 2 例不变。原始缓存离线重算已逐项验证本轮 9/9 PCM 和参考 SHA 一致。参数、依赖和缓存用法见 [评测脚本说明](../scripts/benchmarks/README.md)。

最终用编译后的 Vite Worker、编译后的 Transformers.js bundle 与真实 ONNX WASM 重新运行 F00A，smoke 完整结束。与此前原始观察及候选重放逐项比较：真实 q4f16 token、解码参数、完整 Worker 输出、解码器输出及 stride 均通过；仅一个窗口的解码元数据变为 `[25, 0, 0]`，得到3个字幕段，正文与 4/52 词错保持不变。编译 Worker SHA256 为 `0e9a8aa62f7cbfba18c30886d6ee0a1ad72eb8fb0b5d92498ed1bac5741e2268`。这是额外一次真实推理，但不是新增独立录音，也不是11例都重新跑了一遍编译产物。

`npm test` 实际通过 **201/201**，失败、取消和跳过均为0；完整静态构建成功，总体积434.2 MiB，包含模型资产，并非首屏下载大小。单例 smoke 的宿主耗时为76.24秒，不作为浏览器或手机速度承诺。净化后的完整 smoke 输出、比较结果和日志SHA已写入两份结果JSON。上述检查仍不覆盖真实鸿蒙手机、浏览器媒体解码或端到端录像OCR。
