# 转写准确率拆解与本轮验证

## 结论

转写系统一直使用模型。早期常见声学模型、发音词典、语言模型和搜索算法；今天的端到端模型也需要合适的音频处理、解码与结果判断。REA 用于分析软件如何组织这些环节，不能凭空恢复商业服务的训练数据或模型权重。

本轮保持浏览器本地处理，不引入按次收费的接口。默认采用高精度模型，并保留快速模型、明确中文、近静音分段、异常重复提示、单模型内存释放以及重转/恢复。演唱会歌声样本仍存在明显漏字和幻觉，不能宣布该样本准确率已经修复。

## 当前库的限制与本轮落地

本项目固定使用 Transformers.js 3.8.1。核对安装版本的实际代码发现：未指定语言时默认英语，自动语言检测尚未实现；生成过程尚未真正分叉多个 beam；`prompt_ids`、完整生成分数及 Python Whisper 的概率阈值回退不能仅靠增加同名参数获得。

因此，本轮明确传入中文或英语，移除假的自动语言选项，不添加没有生效的束搜索或置信度参数。双声道只有近乎完全反相抵消时才保留最强声道，普通混音仍求平均，不增加音量。音频按极保守的近静音阈值分段，连续停顿至少 1.5 秒才切割，保留约 0.3 秒上下文，字幕恢复到原音频的绝对时间。近静音检测不是语音 VAD，也不能识别、消除伴奏。连续重复及长声音段的过少文字仅提示校对，不删除原文、不编造置信度分数。

用户可在完成后重新转写当前文件，失败或停止仍保留编辑过的原稿。未手动改变精度时，快速重转升级到 Small；成功后可以恢复上一版的正文、时间轴和设置。切换识别模型前释放上一模型，避免两种模型同时驻留内存。

## 实际对比与适用边界

对一段 21.696 秒、存在伴奏与现场混响的歌声，检查了有效 PCM、响度和双声道相关性。Tiny/Base q8、Base 高精度编码器、Small q8、SenseVoice int8、Vosk 小中文模型以及 UVR 人声分离均做了本地真实推理实验；这些方案均没有恢复可靠的完整歌词。最终 Small q4f16 的实际 WASM 也对该歌声发生漏识别，已触发稀疏文字提示。减少重复、输出更长或运算更快都不等于准确率提高。

发布配置为 Tiny q8 与 Small q4f16。两套模型资产约 235.2 MiB，采用已实际验证的约 11 MB 标准 WASM 运行库，删除重复运行文件，使部署包满足 256 MiB 限额。模型压缩用于减少资源体积，本身不等于准确率提高。

另外使用官方 5.592 秒普通中文短句比较。Small 输出与官方示例的词汇内容一致；Vosk 小模型也识别出相同词汇内容但缺少标点和数字规整。该参考是官方公布的示例结果，不是独立人工金标；一个短句不能推出普遍排名或准确率百分比。

真实 WASM 检查执行生产 Worker、模型加载器及浏览器推理库。测试环境模拟 Cache API，并将 WASM helper 地址映射到本地；不代表 Chrome 中的解码、点击流程或所有设备通过。模型资源可在部署后通过真实 HTTPS 单独验证。

进一步训练需要有正确文本的多条音频、独立验证集和训练算力。单个片段不适合用来证明微调泛化。优先建立讲话、噪声、专业词、长录音等样本集，再决定是否接入神经 VAD、热词重评分或新的解码后端；歌曲歌词需要另行评估。
