# v0.5.1 采访正确性与 REA 优化记录

本轮修复了两处会遗漏采访内容的应用缺陷，并增加两种可恢复的重试策略。**默认模型与默认音频/窗口策略未变，不能宣称整体识别率大幅提高或所有用例通过。** 参考文本只进入事后评分器，没有进入模型、词典、提示词或输出修补。

## 实际修复

- 自动视频模式即使读到可靠画面文字，也继续识别完整音轨。人名条、标题等保留在候选区，不代替整场采访。仅用户选择“仅识别画面字幕”才返回 OCR 正文。测试实际执行生产 UI 事件处理器，包含短人名条、无音轨视频重试、停止和恢复；未把合成 OCR fixture 称为真实录像正确性证明。
- Whisper 的某个字幕段时间无效、或字幕与正文不完整对应时，保留该音频范围全部正文并明确标注粗略时间，避免 SRT/VTT 悄悄漏句。有效范围仍保留原时间。SenseVoice 不再将 2.5 / 0.05 中的小数点切成句末。
- 中文增强的“按原话”重试保留原来的 ITN 关闭路径，并对低音量尝试有上限的线性增益；默认不放大。固定规则为整段 RMS 大于 1e-5 且小于 0.01 时，目标 0.04，上限 8 倍，峰值不超过 0.95。不改变采样数、语速或声道；原 PCM 先做人声检查及窗口选择，仅复制单个最多 30 秒窗口。它不是降噪，长静音会影响 RMS，所以仅作为可恢复重试，JSON 记录 audioGain。
- 英文 Whisper 的正文重试改用 20 秒窗口 / 3 秒重叠，默认时间戳识别仍为 30 / 5。没有按输出长短、模型“自信”或已知答案自动挑胜者；原稿和手工修改可恢复。

## REA 做了什么

使用官方 rea-agents 6.4.0 的 import-reference-source 分析 Whisper Web 与 Transcribe.js，得到 42 / 80 个源码条目、34 / 39 条关系，均无解析失败。完整 analyze-javascript-application 已实际执行并重试，但被宿主 procps 的进程检查阻断。两类记录均保留，未关闭检查或将失败记为完整成功。

源码对照帮助核查窗口、起音上下文、VAD、解码回退及时间对齐机制。Whisper Web 的 30 / 5 本项目原本已有，不重复算作本轮改进。模型参数、词表和权重未修改，没有训练或逆向云端商业模型。详见 [源码研究与原始 REA 记录](benchmarks/REA_ASR_RESEARCH.md)。

## 真实采访与分数

采用 MELI 1.2 的 6 段自然访谈回答，合计约 184.66 秒，4 段中文、2 段英文、5 位不同受访者；M00A 的中英文是同一人。最初 4 段属于开发用例，随后固定的 F01A / M00B 是针对既定增益规则的保留验证用例，不据此调整参数。

官方参考为 Whisper-large-v3 初稿经双语研究助理人工校正，不是完全从零人工转录。仅受访者左声道有完整标注，英文包含非母语口音。这不是多人说话人区分、整场问答或英语母语总体评测。原标注刻意省略大多数标点，**本批标点准确率不计分**；产品仍输出标点，但不能据本批声称标点全部正确。

字符/词错误率为替换、漏词、插入的编辑距离除以参考长度，越低越好；保留语气词与真实重复，不能把 1−CER 当作普遍准确率。详细来源、冻结 SHA 和复现入口见 [MELI 说明](benchmarks/MELI_INTERVIEWS.md)。

| 用例 | 度量 | 默认识别 | 旧重试 | 本轮重试 |
|---|---|---:|---:|---:|
| F01B 中文，25.62 秒 | CER | 7/125 = 5.60% | 7/125 = 5.60% | 6/125 = 4.80% |
| M00A 中文，35.97 秒 | CER | 10/185 = 5.41% | 10/185 = 5.41% | 10/185 = 5.41% |
| F01A 中文保留验证，21.44 秒 | CER | 3/81 = 3.70% | 3/81 = 3.70% | 3/81 = 3.70% |
| M00B 中文保留验证，28.05 秒 | CER | 3/54 = 5.56% | 3/54 = 5.56% | 3/54 = 5.56% |
| F00A 英文，34.69 秒 | WER | 4/52 = 7.69% | 4/52 = 7.69% | 4/52 = 7.69% |
| M00A 英文，38.88 秒 | WER | 27/103 = 26.21% | 30/103 = 29.13% | 28/103 = 27.18% |

中文开发用例重试合计只减少 1 个字错；两个保留验证用例没有改善。英文新重试比旧重试少 2 个词错，但 M00A 仍略差于默认结果。因此重试不保证优于原稿。F01B 的“系统”在最终重试中仍误听，M00A 英文还有省略和误听，不能记为逐字通过。

## 未采用与失败实验

| 实验 | 观察 | 决策 |
|---|---|---|
| SenseVoice 静音候选窗口由 40 ms 延到 400 ms | 两段开发中文 CER 完全未改善 | 不采用 |
| 中文仅关闭 ITN | 采访字错数未改善；数字书写形式会变化 | 保留已有显式重试，不当成新默认改进 |
| 默认识别加增益（探索） | NumPy float32 预处理曾得 F01B 4.0%；实际 JS 乘法得 4.8%，对数值细微差异敏感 | 不使用初探数冒充产品结果，不改默认 |
| 英文仅切正文解码 | M00A 26.21% → 29.13%，变差 | 默认保留时间戳识别 |
| 英文时间戳模式改 20 / 3 | F00A 仍 7.69%，M00A 22.33% | 仅两段开发证据，不替换全局默认 |
| 英文正文模式 20 / 3（最终重试） | M00A 旧正文 29.13% → 27.18%；F00A 不变 | 作为可恢复的重试，不自动覆盖原稿 |
| 英文基线并行实验退出 137 | 首例已完成，第二例无结果；容器记录一次 OOM kill | 不算识别错字，第二例单独复跑完成，WER 26.21% |

中文最终组合和单独增益的输出不同，分别保留；不能把“时间戳模式加增益”的字词修正归到“正文模式加增益”。所有未采用实验及部分完成运行均列入 [结果 JSON](benchmarks/interview-results.json)，没有挑掉困难样本。

## 旧用例回归与验证边界

恢复了旧集合的 10 项公开用例：5 段独立公开录音、3 个同源派生控制、2 个合成无语音控制。全部 PCM SHA 和参考文本与旧清单逐项一致；没有访问缺失的私有歌词视频。中文默认快语速仍为 20/130 = 15.38% CER；嘈杂号码仍为 46/53 = 86.79%，默认失败未解决。按原话重试该号码为 27/53 = 50.94%，仍错误很多，不能算通过。旧低音量/合成伴奏用例的按原话模式仍可能把“开放”写成“开饭”，默认该项正确；原结果可恢复。

最终低音量组合相对旧按原话重试，除 F01B 外的 13 项**输出文本逐字相同**，不只是编辑距离相同；M00B 的增益为约 6.245 倍但文字未改善。静音与纯噪声仍在原始 PCM 人声检查后暂停，没有生成正文。英文新重试对旧 JFK 词错率为 0，旧嘈杂对话为 6/31 = 19.35%；这不表示本轮缩窗单独带来的收益。

最终默认识别另对14项全部复跑，逐项正文与评分对象均与本轮原版基线完全一致。181 项 Node 逻辑测试通过。真实模型评测调用构建后的 SenseVoice / Silero / 标点 Worker 与真实 WASM，Whisper 使用生产 worker 源码、构建后的 Transformers.js 和真实 ONNX WASM；仅 HTTP、Cache API 与 Worker 传输由 VM 替身提供。参考只在推理后评分。**不覆盖真实手机浏览器解码、完整录像 OCR 或鸿蒙设备兼容性。** 媒体输入只在本地读取，模型网络模拟器只允许资产 GET；未向远程模型上传录音。
