# v0.4.1 重试策略实测

高精度声音识别的同设置重试，交替调用模型实际支持的 `return_timestamps:true/false`。默认方式不变；仅正文方式输出每个原始声音范围的粗略时间，不声称逐句对齐。切换语言/来源/精度时采用该设置的正常解码，不悄悄更换模型。

以下是当前生产 Worker 的真实 Small q4f16 + Transformers.js 3.8.1 浏览器 bundle + 单线程 ONNX WASM 五例运行；清单及原始输出见 [JSON](benchmarks/results-v041-text.json)。参考文本仅在推理之后评分。传输与 Worker 由 Node VM 模拟，不是手机端完整验收。分数去空格与标点但不抹去数字/繁简差异；CER是字符错误率，越低越好。

| 样本 | 既有默认方式 CER | 当前仅正文重试 CER | 结论 |
|---|---:|---:|---|
| zh-clean | 0% | 0% | 文字一致，有句号 |
| zh-fast | 100% | 99.23% | 仍未通过 |
| zh-noisy-digits | 100% | 77.36% | 仍未通过 |
| en-noisy-dialogue | 19.85% | 10.69% | 仍未通过 |
| user-lyrics | 100% | 90.91% | 仍未通过 |

英语嘈杂对白的 WER 从既有默认方式 29.03% 降至本次 19.35%；仍有错词和漏词，不能称为通过。嘈杂中文中数字书写等价后的 CER 为35.85%，也仍有实际号码错误。不能将输出字数变多当作内容正确。歌词音轨仍失败，应将画面证据作为另一来源；此重试不改变OCR结果。

此前的0.75倍放慢、6秒小块识别也未达标，后者在嘈杂号码样本产生大量重复字。它们未成为默认或重试策略。更强模型的后续失败和资源成本见 [语音实验记录](FAILED_ASR_EXPERIMENTS.md)，画面候选上下文实验见 [OCR语境实验](CONTEXTUAL_OCR_EXPERIMENT.md)。

重试成功、失败和停止均保留原稿；成功后可恢复上一版。人声检测若暂缓生成文字，用户可强制识别原音；这个选择按文件持续生效，失败/停止后重试及恢复旧结果不会撤销它，其他文件不受影响。正文解码变化和粗略时间保留在JSON及界面提醒中。行为测试不替代这份内容正确性验证。
